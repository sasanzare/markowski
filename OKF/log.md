* **Added**: Stage 4 — Markowski proposes operations, not whole documents. An edit now arrives as `{"type": "document_operations", "operations": [{"op": "replaceBlock", "block": "b2", …}]}`: scoped changes addressed by short block handles (`b1`, `b2`, …) rather than UUIDs, which are the wrong thing to ask a model to copy. Blocks the assistant doesn't mention cannot change, because nothing else is described. Decoding validates before anything is applied — an invented handle, an unknown operation, or a missing field is refused by name — and batches are all-or-nothing, so a half-applied edit can't exist. The proposal now carries a plain-English line per change ("Rewrite paragraph “One sentence about…”", "Add a row to table"), shown in the review card before any diff. The old `updated_document` envelope is still accepted.
* **Fixed**: The formatting panel's table controls reach tables again. Once a table became a text attachment, nothing reading Markdown source could see the caret inside one, so the panel's whole table section was permanently disabled with no error to show for it. A `TableSelectionBridge` now carries the focused cell up from the grid through the attachment to the panel, and carries commands back down; Source mode converts its own text-based table finder into the same shared `TableEditingContext`, so the panel works identically on both surfaces without knowing which it is driving. Releasing focus is grid-specific, because moving between two tables fires the old grid's resign after the new one's become.
* **Added**: Stage 3 — tables are objects. A table now occupies a single `NSTextAttachment` in the canvas, backed by `DocumentTableView`: a real grid whose every cell is its own text view, with Tab/Shift-Tab/Return moving between cells, tabbing off the end adding a row, hover affordances for adding rows and columns, content-proportional column widths, per-column alignment, and right-to-left column order for Persian tables. Structural edits mutate the `TableBlock` and report through the attachment, since edits inside an attachment never reach the outer text view. Reading a table back is a read of the model, not a re-parse. Two real bugs surfaced on the way: declaring a designated initialiser on an `NSView`/`NSTextView` subclass left AppKit's own initialisers as trapping Swift stubs (every table crashed the process), and cells on the default TextKit 2 stack have nil `textStorage` and `layoutManager`, so their content never appeared and every row measured to the same fallback height — cells now use an explicit TextKit 1 stack while the canvas stays on TextKit 2.
* **Added**: Stage 2 — the WYSIWYG canvas. Preview is now a real `NSTextView` on TextKit 2 editing the document directly, with block structure held in attributes (`.mvParagraph` carrying a block id and role) rather than as visible syntax: no `#`, `**`, or `](` ever appears in the canvas. Typing mutates `NSTextStorage` and re-projection happens only when the document changes from outside, so the caret never jumps and nothing is rebuilt per keystroke. Presentation and meaning are separate channels — fonts are typography, `.mvInlineStyle` is semantics — after the projection test caught heading typography being read back as `**bold**` content. Chrome (bullets, checkboxes, cell separators) is protected from editing, Tab moves between table cells, and each paragraph takes its writing direction from its own text. The rendered WebView stays available under View Options ▸ Rendered Preview (legacy), and still handles Mermaid.
* **Added**: Stage 1 of the document-architecture inversion — a block `RichDocument` model (blocks, styled inline runs, real table objects, stable per-block identity) with a Markdown parser and serializer as its only storage format, and a `DocumentOperation` layer giving the editor and the assistant one addressable vocabulary for change (replace a block's text, set a heading level, toggle a style over a character range, insert/delete/move blocks, mutate table cells, rows, columns, and alignment). Batches are all-or-nothing, and addressing a deleted block is an error rather than a silent no-op. The parser/serializer pair is held to a round-trip fixed point by hand-written cases, the repository corpus, every starter template, and 300 generated documents per run — which caught a code fence shorter than its own content, checkboxes ignored after an ordered list marker, and task lists modelled as their own list style when Markdown treats them as bulleted items with a checkbox. The canvas, tables-as-objects, assistant routing, and retiring the WebView preview are stages 2–5 and are not built yet.
